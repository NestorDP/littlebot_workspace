# Littlebot Engineering Workspace

The `littlebot_workspace` repository is the central integration and engineering workspace for the Littlebot project.

It coordinates the multi-repository development environment and provides a home for system-level documentation, repository manifests, and workspace maintenance tools. Subsystem implementation remains in its owning repository.

## Repository responsibilities

- `littlebot_workspace`: system integration, engineering documentation, manifests, and workspace tooling.
- `littlebot`: ROS 2 software.
- `littlebot_firmware`: embedded firmware.
- `littlebot_gazebo`: robot simulation.
- `littlebot_rqt_plugin`: ROS 2 graphical interface.
- `littlebot_hardware`: mechanical and electrical design.

## Development workspace layout

Keep this repository **outside** the colcon source directory. A recommended layout is:

```text
littlebot-dev/
├── littlebot_workspace/   # This repository; engineering coordination
├── src/                   # Repositories imported for development
├── build/                 # Generated by colcon
├── install/               # Generated by colcon
├── log/                   # Generated by colcon
└── .deps/                 # Optional locally built dependencies
```

The directory containing `src/` is the colcon workspace root. Do not clone `littlebot_workspace` into `src/`.

## Import repositories

Install the ROS 2 development tools and vcstool for your ROS distribution, then run these commands from the parent directory (for example, `littlebot-dev/`):

```bash
mkdir -p src

vcs import src < littlebot_workspace/manifests/littlebot.repos
vcs import src < littlebot_workspace/manifests/third_party.repos
```

The project manifest pins each Littlebot repository to a verified commit because those repositories do not currently publish release tags. The third-party manifest uses release tags. See [manifest conventions](manifests/README.md) before updating revisions.

## Build the ROS 2 workspace

After importing the repositories, source the setup file for your installed ROS 2 distribution and build from the parent directory:

```bash
source /opt/ros/<ros-distro>/setup.bash
colcon build
```

Only repositories containing compatible ROS 2 packages are expected to be built by colcon. Firmware and hardware-design workflows remain repository-specific.

## Directory guide

- [docs/](docs/README.md): central engineering and integration documentation.
- [manifests/](manifests/README.md): vcstool manifests for project and third-party repositories.
- [tools/](tools/README.md): scripts and utilities for workspace setup and maintenance.

## Scope

This repository does not replace the subsystem repositories. It records system-level decisions and interfaces, coordinates integration, and provides reproducible instructions for assembling the development workspace.
